### 3.1 阻塞：xl 锁误报（✅ 已修）
- 现象：`xl ramdisk` / 任何非只读命令报 `xl: a run is in progress: only state...`，但没有任何运行。
- 根因：WSL 的 `Failed to start the systemd user session for 'root'` 导致 `/run/user/0` 不存在；`xl` 的锁文件在该目录，`flock` 无法创建文件即返回失败，被当成"别人的运行正在进行"。
- 修复：`xl` 在设置 `PHONE` 后 `mkdir -p "$(dirname "$PHONE")"`。修复后 `xl state` 正确返回 `loader`，截图/上传恢复正常。
- 教训：这条误报会同时挡住 `stop`/`reboot` 之外的救援动作，属于**必须修**的真缺陷。

### 3.2 运行环境的两个坑（都已在本次处理）
1. **`flock` 目录缺失导致"假运行中"**：见 3.1，已在 `xl` 里 `mkdir -p` 修复。
2. **`fastboot` 是 Windows 的 `fastboot.exe`**（`/usr/local/bin/fastboot` 指向 `fastboot.exe`）。它读不了 `/mnt/s/...` 这类 Linux 绝对路径，只会把 WSL 当前目录翻译成 Windows 目录，所以**相对路径能用、绝对路径报 `cannot load`**。上传大根要先把文件放进构建树（`userland/system-1105.apfs`），再用相对路径 `./xl ramdisk userland/system-1105.apfs`。

### 3.3 一个容易搞错的启动参数
- PCLM10 的触摸驱动是 **`hakios.s3706.c`（Synaptics S3706，I2C 0x20，`synaptics19081@20`）**，由 **`touch=1`** 打开；`hakios.bq27541.c` 也读 `touch=1` 用于触摸供电/引脚归属保护。
- `touchscreen=1` 是另一条 Goodix GT9916 路径（`hakios.goodix.c` / `hakios.buttons.c`），本机 **不应** 传（`pclm10.config` 里 `CONFIG_TOUCHSCREEN` 未开，goodix/buttons 未编进内核）。
- 所以 defconfig 的 `touch=1` 是**正确**的，之前怀疑"参数写错导致无触摸"不成立。
